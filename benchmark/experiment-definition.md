# AI 문서 작성 비교 실험 정의서

## 1. 실험 목적

본 실험의 목적은 동일한 요구사항과 동일한 입력 문서를 기반으로 ChatGPT와 Claude가 각각 독립적으로 문서를 작성한 뒤, 서로의 결과물을 평가하여 문서 작성 능력과 판단 품질을 비교하는 것이다.

단순히 어느 모델이 더 좋은 결과를 냈는지를 확인하는 것이 아니라, 다음 항목을 확인하는 것을 목표로 한다.

- 요구사항 이해 능력
- 문서 구조화 능력
- 논리적 완성도
- 실무 적용 가능성
- 기술적 정확성
- 구체성과 실행 가능성
- 불필요한 내용 최소화
- 누락 사항 발견 능력
- 다른 모델의 결과물을 객관적으로 비평하는 능력

---

## 2. 실험 대상

- ChatGPT
- Claude

두 모델에는 가능한 한 동일한 조건을 제공한다.

### 공통 조건

- 동일한 원본 문서 제공
- 동일한 작성 요청 제공
- 동일한 출력 형식 요구
- 상대 모델의 결과물을 보기 전에 1차 문서 작성
- 1차 작성 완료 후 상대 모델의 결과물 제공
- 동일한 평가 기준으로 상호 평가 수행

---

## 3. 실험 진행 순서

### Phase 1. 원본 요구사항 정의

사용자가 해결하고 싶은 문제와 문서 작성 목적을 하나의 Markdown 문서로 정의한다.

이 문서는 ChatGPT와 Claude에게 동일하게 제공한다.

---

### Phase 2. 독립 문서 작성

ChatGPT와 Claude는 상대 모델의 결과물을 보지 않은 상태에서 각각 독립적으로 결과물을 작성한다.

결과 파일 예시:

```text
results/
├── chatgpt/
│   └── draft.md
└── claude/
    └── draft.md
```

이 단계에서는 상대 모델의 결과물이나 평가 내용을 제공하지 않는다.

---

### Phase 3. 결과물 교환

두 모델의 1차 결과물이 모두 완료된 이후 결과물을 서로에게 제공한다.

- ChatGPT에게 Claude 결과물 제공
- Claude에게 ChatGPT 결과물 제공

자기 자신의 기존 결과물도 함께 비교 대상으로 사용한다.

---

### Phase 4. 상호 평가

각 모델은 아래 평가 기준에 따라 두 결과물을 모두 평가한다.

즉, 다음과 같이 평가한다.

#### ChatGPT

- ChatGPT 결과물 평가
- Claude 결과물 평가
- 두 결과물 비교
- 항목별 우세 모델 판단
- 전체 우세 모델 판단

#### Claude

- Claude 결과물 평가
- ChatGPT 결과물 평가
- 두 결과물 비교
- 항목별 우세 모델 판단
- 전체 우세 모델 판단

자기 결과물이라고 해서 가산점을 부여해서는 안 된다.

---

## 4. 평가 기준

총점은 100점으로 한다.

| 평가 항목 | 배점 | 평가 내용 |
|---|---:|---|
| 요구사항 충족도 | 20 | 사용자의 목적과 요구사항을 정확히 반영했는가 |
| 논리 및 구조 | 15 | 문서 흐름과 구조가 명확하고 논리적인가 |
| 기술적 정확성 | 15 | 기술적으로 잘못된 설명이나 오해의 소지가 없는가 |
| 구체성 | 10 | 추상적인 설명이 아닌 구체적인 내용이 포함되어 있는가 |
| 실행 가능성 | 15 | 실제 업무나 프로젝트에서 바로 적용할 수 있는가 |
| 완성도 | 10 | 중요 내용의 누락 없이 충분히 완성되어 있는가 |
| 간결성 | 5 | 불필요한 반복이나 장황한 내용이 없는가 |
| 실무 가치 | 10 | 실제 개발 및 의사결정에 도움이 되는가 |
| **합계** | **100** | |

---

## 5. 평가 방법

각 항목은 배점 범위 내에서 점수를 부여한다.

평가자는 반드시 점수에 대한 근거를 함께 작성해야 한다.

예시:

```text
요구사항 충족도: 18/20

이유:
사용자가 요구한 핵심 항목은 대부분 반영되었으나,
운영 단계의 예외 처리에 대한 내용이 부족하다.
```

단순히 점수만 작성하는 것은 허용하지 않는다.

## 7. 평가 원칙

### 7.1 자기 결과물 편향 금지

평가자는 자신의 결과물이라는 이유로 높은 점수를 부여해서는 안 된다.

모든 평가는 결과물 자체만을 기준으로 한다.

---

### 7.2 구체적 근거 제시

다음과 같은 평가는 지양한다.

```text
Claude가 조금 더 좋아 보인다.
```

다음처럼 구체적으로 작성한다.

```text
Claude 결과물은 CI와 CD 단계를 명확히 분리했고,
각 단계의 실패 조건과 Human Approval 지점을 구체적으로 정의했기 때문에
실행 가능성 항목에서 ChatGPT보다 높은 점수를 부여했다.
```

---

### 7.3 사실 오류 우선 감점

문장이 매끄럽더라도 기술적으로 잘못된 내용이 있다면 반드시 감점한다.

기술적 정확성은 표현력보다 우선한다.

---

### 7.4 길이는 품질 기준이 아니다

문서가 길다는 이유로 높은 점수를 부여하지 않는다.

적은 내용으로도 요구사항을 정확하게 충족하면 높은 점수를 받을 수 있다.

---

### 7.5 누락 사항 평가

평가자는 상대 결과물의 장단점뿐 아니라 다음도 확인한다.

- 두 모델 모두 놓친 내용
- 원본 요구사항 자체에서 부족했던 부분
- 추가하면 실무 가치가 높아질 내용

## 9. 실험 시 주의사항

### 동일 입력 유지

두 모델에게 제공하는 요구사항은 문장 하나까지 가능한 한 동일하게 유지한다.

### 선행 결과 노출 금지

1차 작성 전에는 상대 모델의 결과물을 제공하지 않는다.

### 평가 기준 사전 고정

결과물을 확인한 이후 평가 항목이나 배점을 변경하지 않는다.

평가 기준 변경이 필요한 경우 해당 실험을 종료하고 새로운 버전으로 다시 수행한다.

### 모델 및 환경 기록

가능하면 다음 정보를 함께 기록한다.

```text
실험 날짜:
모델:
모델 버전:
CLI / Web / API:
사용한 추가 설정:
원본 Prompt:
```

이를 통해 향후 모델 버전이 변경되었을 때 동일 실험을 다시 수행할 수 있다.

## 11. 향후 확장

초기에는 문서 작성 능력 비교부터 시작한다.

이후 동일한 방법론을 다음 영역으로 확장한다.

```text
문서 작성 비교
        ↓
코드 생성 비교
        ↓
버그 수정 비교
        ↓
코드 리뷰 비교
        ↓
테스트 생성 비교
        ↓
CLI Agent 비교
        ↓
Single Agent Workflow
        ↓
Multi-Agent Workflow
        ↓
GitHub Actions 연동
        ↓
CI/CD 자동화
```

궁극적으로는 단순한 모델 성능 비교가 아니라,

> 어떤 AI Coding Agent를 어떤 개발 단계에 배치하는 것이 가장 효과적인가

를 실험적으로 검증하는 것을 최종 목표로 한다.
